# HelixServe v0.1.0

HelixServe v0.1.0 is the first versioned snapshot of the single-GPU serving runtime.
It includes paged KV cache allocation, continuous batching, chunked prefill, prefix
cache reuse, CUDA Graph decode replay, a Triton RMSNorm kernel, and runtime metrics
for TTFT, ITL, throughput, queue depth, and KV utilization.

## Measured run

The numbers below come from the checked-in GCP run recorded on 2026-04-06. The
machine was one NVIDIA L4 on a `g2-standard-4` VM. The backend was the toy decoder
backend using `sshleifer/tiny-gpt2` so the runtime behavior could be measured without
claiming model-quality results.

The live suite used 200 requests at concurrency 16 for short, long, mixed, and
repeated-prefix workloads. The burst run used 400 requests at concurrency 64.

| Workload | Throughput | TTFT p95 | E2E p95 |
| --- | ---: | ---: | ---: |
| Short | 1044.53 tok/s | 0.179 s | 0.401 s |
| Long | 837.47 tok/s | 0.342 s | 0.559 s |
| Mixed | 981.16 tok/s | 0.239 s | 0.447 s |
| Repeated prefix | 1092.27 tok/s | 0.159 s | 0.369 s |
| Burst | 1208.43 tok/s | 0.636 s | 1.489 s |

The phase run started at 175.80 tok/s with 3.280 s E2E p95. With continuous
batching, prefix reuse, and CUDA Graph replay enabled it reached 1007.84 tok/s with
0.799 s E2E p95. Prefix hit rate reached 0.998 in that phase.

There is an important caveat. The measured Triton path improved ITL but increased
TTFT p95 to 2.411 s in this run because of cold-start and JIT overhead. That path
needs a warm-up policy before it should be treated as a default optimization.

## Reproduce it

Start the server on a CUDA machine and run:

```bash
python -m bench.run_live_suite --url http://127.0.0.1:8000 --stream
```

The original raw results are in
[`docs/results/20260406T200700Z`](../results/20260406T200700Z), with the phase
comparison in
[`docs/results/phase_table_20260406T195247Z`](../results/phase_table_20260406T195247Z).
The longer methodology and setup notes are in
[`docs/reports/gcp_l4_live_report_2026-04-06.md`](../reports/gcp_l4_live_report_2026-04-06.md).

## Looking for another run

The useful next contribution is a comparable run on a different GPU or with a
real decoder model. Please keep the command, concurrency, token limits, model
name, and raw JSON artifacts together so the result can be compared rather than
turned into a one-line speed claim. Open an issue with the hardware and workload
before sending a larger change.
